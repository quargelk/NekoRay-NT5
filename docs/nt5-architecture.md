# NekoRay NT5 — архитектура

Документ написан для 0.9.5 и дополнен для 0.9.7-dev1 (текущая версия разработки: одна сборка для
Windows 2000 SP4 и Windows XP SP3; NT 5.0-патч рантайма Go — `nt5-ui/third_party/README.md`).
Устройство программы с 0.9.5 не менялось, кроме удаления TUN в 0.9.6. Совместимость с Windows XP и
Windows 2000 заявляется только в объёме раздела 9; подробности о Windows 2000 — `nt5-win2000.md`.

Связанные документы: `nt5-feature-map.md` (что перенесено из Nekoray),
`nt5-test-checklist.md` (ручные проверки XP и Win2K), `nt5-progress.md` (ход
работ), `../nt5-ui/README.md` (сборка и запуск).

## 1. Что это

NekoRay NT5 — графическая оболочка на C# WinForms для старых Windows. Образец —
Nekoray / NekoBox for PC 3.17 (Qt, C++17); его исходники в репозиторий NekoRay NT5 не входят
(они есть в истории Git и в https://github.com/MatsuriDayo/nekoray). Ядро — отдельный процесс
`xray.exe` (Xray 1.8.3, windows/386, собран пропатченным Go 1.20; `nt5-ui/third_party/build-xray.sh`).
Помощник `nt5helper.exe` (Go, тот же тулчейн, только стандартная библиотека)
даёт HTTPS-загрузку с современным TLS. Режим TUN удалён в 0.9.6 (раздел 6.3).

## 2. Жёсткие ограничения

| Ограничение | Следствие |
|---|---|
| .NET Framework 2.0 (в т.ч. RTM 2.0.50727.42), C# 2.0 | Нет LINQ, лямбд, `var`; `LangVersion=ISO-2`, предупреждения = ошибки; не используются API, добавленные в 2.0 SP1 (например, `WaitOne(int)`) |
| x86 | `PlatformTarget=x86`, ядро и помощник — windows/386 |
| Visual Studio 2010 SP1 | `Format Version 11.00`, `ToolsVersion="4.0"`, `Debug\|x86`, `Release\|x86`, без NuGet и предварительных шагов |
| TLS в .NET 2.0 — только SSL 3.0 / TLS 1.0 | HTTPS-подписки через `nt5helper fetch` (TLS 1.2/1.3), затем `curl.exe`; проверка сертификатов не отключается никогда |
| Ядро — штатный `xray.exe` 1.8.3 | Управление через файл конфигурации и перезапуск; статистики трафика нет |
| Go 1.20 с бэкпортами NT 5.1 | Ядро и помощник работают начиная с XP; на Windows 2000 не загружаются (раздел 7) |
| Секреты | UUID, пароли, ключи, ссылки, адреса подписок не попадают в код, журналы и диагностику |
| Исходники Nekoray | Не изменяются; всё новое — в `nt5-ui/` и `docs/nt5-*.md` |

## 3. Размещение

```
nt5-ui/
  NekoRayNT5.sln            решение Visual Studio 2010
  build.cmd                 необязательная сборка того же решения из командной строки
  runtime/                  xray.exe, nt5helper.exe и др.; копируются к программе при сборке (не в Git)
  helper/                   исходники nt5helper (Go) и build.cmd
  tests/                    автоматические проверки (вне решения)
  NekoRayNT5/
    Program.cs              вход, единственный экземпляр, обработчики сбоев
    App/                    сведения о программе, пути, диагностический журнал
    Model/                  ProfileEntry, ProfileGroup, AppSettings
    Services/               ссылки, проверка, хранилища, подписки, конфигурация Xray, системный прокси, тесты
    Core/                   процессы ядра и помощника, проверка исполняемых файлов, очистка после 0.9.x
    Platform/               P/Invoke: WinINet, iphlpapi (TCP-таблица), реестр (автозапуск)
    UI/                     формы
```

## 4. Слои и хранилища

```
UI (формы)  ->  Services  ->  Core (xray.exe, nt5helper.exe)
                          ->  Platform (WinINet, iphlpapi, реестр)
```

- Формы не содержат логики профилей, конфигурации и системных вызовов.
- Все фоновые задачи идут через `MainForm.RunAsync`: исключение там
  записывается в журнал и не завершает программу.
- Системный прокси (`IProxyBackend`) отделён от Windows интерфейсом; логика проверяется на подставных
  реализациях, настоящие настройки в тестах только читаются.

Каталог данных: `%APPDATA%\NekoRayNT5` (переменная `NEKORAY_NT5_DATA_DIR`
задаёт другой).

| Файл | Содержимое |
|---|---|
| `profiles.xml` (+ `.bak`) | Группы и профили, формат 2; порядок элементов — порядок в списке; результаты тестов и метка «из подписки» |
| `settings.xml` | Настройки (поля `tunMode`, `tunAdapter`, `tunDns` версий 0.9.x игнорируются и исчезают при следующем сохранении) |
| `system-proxy-backup.xml` | Исходные настройки прокси; существует, только пока прокси включён программой |
| `run\core.pid` | PID и время запуска ядра |
| `run\tun.pid`, `run\tun-state.xml` | Только от 0.9.x: при запуске оставшийся помощник TUN останавливается (если совпали PID, время и путь), файлы удаляются (`LegacyCleanup`) |
| `logs\nekoray-nt5.log`, `logs\crash.log` | Диагностика оболочки (без вывода ядра и без секретов) |

### 4.1. Защита `profiles.xml`

| Ситуация | Поведение |
|---|---|
| Обычная запись | Временный файл → замена; прежняя версия в `profiles.xml.bak` |
| Файл повреждён | Копия `profiles.xml.damaged-<дата>`; загружается `profiles.xml.bak`, если он читается (иначе пустой список) |
| Две записи с одинаковым id | Вторая получает новый id; ничего не теряется; исходный файл копируется в сторону |
| Часть записей некорректна | Пропускаются, исходный файл копируется в сторону |
| Формат 1 (0.2.0) | Читается; перед первой записью копия `profiles.xml.v1-backup` |
| Формат новее | Файл не трогается, сохранение отключено |
| Запись не удалась | Изменение в памяти откатывается |
| Экспорт/импорт резервной копии | Preferences → Export/Import profile backup; импорт только добавляет (новые id, новые группы) |

Секреты лежат в `profiles.xml` открытым текстом (шифрования нет).

## 5. Подключение

### 5.1. Конфигурация (`XrayConfigBuilder`)

Входы `socks-in` (UDP включён) и `http-in` на раздельных портах (по умолчанию
2080/2081); выходы `proxy`, `direct`, `block`; маршрутизация block → proxy →
direct → частные адреса → выход по умолчанию. Каждая конфигурация проверяется ядром
(`xray run -test`) до запуска.

### 5.2. Жизненный цикл (`CoreController`)

Единственный путь подключения — `MainForm.StartProfile`: Start, Enter, двойной
щелчок, трей и «Remember last profile».

| Ситуация | Поведение |
|---|---|
| Запрос того же профиля во время Connecting/Running | Игнорируется (`StartResult.AlreadyActive`), второго процесса нет |
| Запрос другого профиля | Безопасное переключение: старое ядро останавливается, затем запуск нового; при быстрых повторных запросах выполняется только последний |
| Состояние Connecting | Выставляется синхронно в момент запроса |
| Stop во время Connecting | Запуск отменяется, ядро не остаётся |
| Ядро нельзя загрузить на этой ОС | Проверка PE до запуска (`ExecutableCheck`): понятная причина, Start недоступен |
| Занятый порт | Проверка через таблицу TCP (`GetTcpTable`) и пробный bind |
| Неверная конфигурация | Error с текстом ядра |
| Ядро упало | Error, системный прокси восстанавливается |
| Аварийное завершение оболочки | Job Object; при следующем запуске — `run\core.pid` (процесс завершается, только если совпали PID, время запуска и путь) |

Вывод ядра проходит через `SecretMask` и на диск не пишется.

## 6. Системный прокси, подписки

### 6.1. Системный прокси

`SystemProxyManager` + `WinInetProxy` (WinINet per-connection, ANSI-функции,
LAN и подключения RAS). Исходные значения всех подключений сохраняются до
первого изменения; восстановление при Stop, Exit, ошибке ядра, завершении
Windows и при следующем запуске после сбоя. Раз в 5 с проверяется, не изменил
ли настройки пользователь или другая программа; если изменил — программа
снимает свою отметку и ничего не перезаписывает.

### 6.2. Подписки (`Subscription`, `ProfileStore.MergeSubscription`)

- 0.9.5: единая команда Add (`Services/AddSource.cs`, `UI/AddForm.cs`) —
  распознаёт ссылки, адреса, `happ://add/`; адрес скачивается и разбирается до
  сохранения; подписка создаётся из проверенного содержимого. Маршрут загрузки
  (`SubscriptionClient`): Auto / Proxy / Direct; повтор напрямую только если
  сбой случился до ответа сервера (`FetchException.ServerAnswered`). HWID
  (`Services/Hwid.cs`) — по флажку подписки; заголовки передаются помощнику
  файлом. Ответные заголовки — по белому списку (`profile-title`,
  `subscription-userinfo`, `x-hwid-*` и др.).
- Server → Subscription: Add (сразу загружает), Update this / Update all,
  Import subscription from file.
- `http://` — встроенный клиент с ручными перенаправлениями (не более 5;
  HTTPS→HTTP запрещён). `https://` — `nt5helper fetch` (TLS 1.2+, корни из
  `cacert.pem` пакета, который программа передаёт явно через `-ca`; без файла —
  хранилище Windows, на XP устаревшее). Повреждённый или пустой `cacert.pem` —
  ошибка до подключения, а не переход на хранилище. Затем `curl.exe`
  (`--proto =https`, без `-k`), затем встроенный клиент. При работающем ядре
  загрузка идёт через него, при неудаче — напрямую.
- Отклоняются: HTTP-ошибки, HTML-страницы, двоичные данные, «картинки» и т. п.
  по MIME-типу, пустой ответ, более 5 МБ. Содержимое: список ссылок, Base64
  (обычный/URL-safe, с переносами), percent-encoded.
- Слияние: совпадение по параметрам подключения, иначе по уникальному имени
  того же типа → id, позиция и результат теста сохраняются; новые добавляются в
  конец; исчезнувшие удаляются; профили, добавленные вручную в группу
  подписки, и другие группы не трогаются; дубликаты в самой подписке
  отбрасываются. Неудача — профили не меняются, причина видна на вкладке
  (`[sub !]`) и в строке состояния; одновременное обновление одной подписки
  запрещено.

### 6.3. TUN — удалён в 0.9.6

Режим TUN (TAP-Windows 9.9.x + `nt5helper tun` на gVisor) был в 0.9.1–0.9.5,
на XP так и не заработал и удалён продуктовым решением. Удалены: флажок и пункты
меню TUN, вкладка Settings → TUN, проверки TAP/прав/TUN и установка драйвера в
Diagnostics, `TunSession`, `RouteTable`, `TapAdapters`, команды помощника `tun` и
`tap-check` и его зависимости (gVisor, x/sys, x/time, btree). Исключение правил
`direct` «для TUN» в конфигурации тоже убрано: правила direct применяются всегда.
Программы, не использующие системный прокси, подключаются к локальным портам
SOCKS5/HTTP. После обновления с 0.9.x `LegacyCleanup` убирает `run\tun.pid` и
`run\tun-state.xml`; маршруты не трогаются (они не постоянные и исчезают после
перезагрузки Windows), в журнал пишется подсказка.

## 7. Windows XP и Windows 2000

Актуальный анализ Windows 2000 (матрица, PE-аудит, зависимости рантайма Go,
блокер и план проверки) — `docs/nt5-win2000.md`. Ниже — история.

Причина падения 0.3.0 на Windows 2000 (установлена по коду и бинарникам; на
Win2K не воспроизводилась — VM нет):

1. После `Profiles loaded: 0` оболочка в фоновом потоке запускала
   `xray.exe version` без обработки исключений.
2. `xray.exe` имеет версию подсистемы PE 5.1 (Windows XP) и статически
   импортирует `kernel32!AddVectoredExceptionHandler` (функция появилась в XP).
   Загрузчик NT 5.0 отказывает (`ERROR_BAD_EXE_FORMAT`, 193).
3. `Win32Exception` в фоновом потоке на .NET 2.0 завершает процесс.

Исправлено в оболочке: глобальные обработчики + `crash.log`; все фоновые задачи
перехватывают исключения; `ExecutableCheck` до запуска разбирает PE (версия
подсистемы, разрядность, наличие каждой импортируемой функции в системе) и
объясняет причину; Start и URL-тест недоступны с понятным текстом.
Проверено на подставной «NT 5.0» и на файле, который Windows не может
запустить (ошибки 193/216) — программа не падает.

| Вопрос | Windows XP SP3 x86 | Windows 2000 SP4 x86 |
|---|---|---|
| Оболочка (.NET 2.0) | 0.9.0 запускалась и подключалась через System Proxy (проверено пользователем); 0.9.1 — **ручная проверка** | Ожидается запуск без падения; **не проверено** (нет VM) |
| Ядро `xray.exe` | Работает (проверено пользователем, VLESS+REALITY+Vision) | **Не загружается**: подсистема 5.1 и `AddVectoredExceptionHandler`. Нужен бэкпорт Go-рантайма к NT 5.0 — отдельная задача |
| `nt5helper.exe` | Запускается (0.9.0: `fetch` дошёл до проверки сертификата) | Не загружается (та же причина) |
| Системный прокси (WinINet) | Код готов; **ручная проверка** | Функции есть с IE 5; без ядра включать нечего |
| Подписки HTTPS | Через `nt5helper` + `cacert.pem` из пакета. 0.9.0 без `cacert.pem`: unknown certificate authority. 0.9.1 — **не проверено** | Только `http://` или импорт из файла |

## 8. Лицензия

GPL-3.0 (как Nekoray); `xray.exe` — MPL-2.0 с GPL-3.0-модулями (распространяется
на условиях GPL-3.0, см. `nt5-ui/third_party/README.md`); `nt5helper` — только
стандартная библиотека Go (BSD-3-Clause). Значок рисуется в коде. Это техническая оценка, а не
юридическое заключение.

## 10. Чего нет

| Функция | Причина |
|---|---|
| Режим TUN | Удалён в 0.9.6 (6.3) |
| Статистика трафика, список соединений | Нужен API ядра (gRPC) |
| QR-код, Clash/sing-box-подписки, цепочки, свой JSON | Отложено |
| TUIC, Hysteria, Naive | Другое ядро |
| Автообновление подписок по таймеру | Отложено (обновление вручную и «Update all») |
| Шифрование `profiles.xml`, темы, перевод | Отложено / косметический этап |
