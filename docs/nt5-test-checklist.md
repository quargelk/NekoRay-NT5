# NekoRay NT5 — ручные проверки

Ручные проверки на целевых системах. Список составлен для 0.9.6; те же разделы применимы к
0.9.7-dev1. Проверяется папка выпуска (`NekoRayNT5.exe`, `xray.exe`, `nt5helper.exe`,
`cacert.pem`, `README.txt`, `licenses\`, `SHA256SUMS.txt`): архив
`NekoRayNT5-v0.9.7-dev1-win32.zip` со страницы Releases или Release-сборка в
`nt5-ui\NekoRayNT5\bin\x86\Release\package\`. Перед копированием на тестовую систему проверьте
суммы (`sha256sum -c SHA256SUMS.txt` в Git Bash). Любой сбой в разделах A–F — повод не называть
версию стабильной.

Результаты ниже получены для 0.9.6: комплект `NekoRayNT5-v0.9.6-rc2` и тестовый комплект
`-portfix-test` с исправлением порта 2081 (раздел M; от `-rc2` отличается только
`NekoRayNT5.exe`, версия в программе та же — 0.9.6). Оба комплекта хранятся в рабочей папке
разработчика вне репозитория.

только по отчёту сопровождающего с XP; автотесты хоста сюда не входят.

| M5, A (VS2010), G (обновление с 0.9.5), остальные строки B–H | — | Не подтверждено | Нет отчёта |

Автотесты хоста (Windows 11, не XP): Debug/Release — 0 предупреждений;
`run-tests.cmd` 348/348; `run-ui-smoke.cmd` 52/52 в каждом из 4 прогонов;
выборочный `TestPlatformReadOnly` 8/8.

Копируйте на VM всю папку пакета: без `cacert.pem` HTTPS-подписки на XP не
загружаются (корневые сертификаты XP устарели).

Перед началом:

- Сделайте снимок VM. Разрушительные проверки (D, G) — только на VM.
- Не копируйте журнал и файлы из `%APPDATA%\NekoRayNT5` в отчёты: там
  настоящие учётные данные. Для отчёта есть Preferences → Copy diagnostic info
  (без адресов, id и ключей) и `logs\nekoray-nt5.log` (без вывода ядра).
- Запишите текущие настройки прокси (Свойства обозревателя → Подключения →
  Настройка LAN) и вывод `route print` — для сверки в D и G.

Предусловия XP: Windows XP SP3 x86, .NET Framework 2.0 (с SP — по желанию),
процессор с SSE2, сеть; настоящий профиль VLESS + REALITY + Vision и адрес
своей подписки — только на VM, в отчёт не копировать.

При любом сбое записать: номер строки, точный текст сообщения (снимок
окна), что было в журнале окна (без адресов и ключей), Diagnostics → Copy
report, `%APPDATA%\NekoRayNT5\logs\nekoray-nt5.log` и `crash.log` (если
есть). Строка считается пройденной только по факту на XP; автоматические
тесты на Windows 11 её не заменяют.

### M. Повторное подключение и порт 2081 (комплект `-portfix-test`)

сервера появлялось «Local HTTP port 2081 cannot be used: it is already used by
another program»; `netstat` показывал только `TIME_WAIT` на 127.0.0.1:2081,
`LISTENING` не было.

| M3 | Disconnect → Program → Exit → снова запустить → Connect | Running; ошибок порта нет; `xray.exe` от прошлого запуска не остаётся |
| M4 | Settings → Connections: HTTP-порт 135 (его всегда слушает Windows XP) → Connect; затем вернуть 2081 | Error «Local HTTP port 135 cannot be used: it is already used by another program...»; после возврата 2081 — Running |

## Windows 2000 SP4 x86 — отдельный план

Полный анализ, матрица совместимости и план W1–W9 — в
`docs/nt5-win2000.md`. С 0.9.7-dev1 `xray.exe` и `nt5helper.exe` собраны для NT 5.0
(`nt5-ui/third_party/go1.20-nt51-nt50.patch`) и те же файлы работают на обеих системах.
Пользователь сообщил, что на Windows 2000 SP4 x86 (.NET Framework 2.0, установленные
сертификаты, без KernelX) работают ссылки VLESS, HTTP-подписки, URL Test, подключение,
отключение, переподключение и трафик браузера через прокси. Построчно по разделам A–M на
Windows 2000 проверка не проводилась; до 0.9.7 ядро там не загружалось.
