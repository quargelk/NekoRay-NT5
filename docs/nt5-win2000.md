# NekoRay NT5 — Windows 2000 SP4: совместимость (анализ 2026-10-17)

> **Актуальный статус (0.9.7-dev1, 2026-10-18).** Вариант 1 (раздел 3) выполнен: рантайм Go
> перенесён на NT 5.0 патчем `nt5-ui/third_party/go1.20-nt51-nt50.patch` (что и почему —
> `nt5-ui/third_party/README.md`, раздел «Windows 2000 (NT 5.0) patches»). Одни и те же
> `NekoRayNT5.exe`, `xray.exe` и `nt5helper.exe` (комплект `NekoRayNT5-v0.9.7-dev1-release`)
> используются на обеих системах.
>
> **Проверено пользователем на настоящих системах (0.9.7-dev1):**
>
> | Система | Конфигурация | Результат |
> |---|---|---|
> | Windows 2000 SP4 x86 | .NET Framework 2.0, установленные корневые сертификаты, **без KernelX** | работают ссылки VLESS, HTTP-подписки, URL Test, подключение, отключение, переподключение, трафик браузера через прокси |
> | Windows XP SP3 x86 | без дополнительных расширений системы | то же |
>
> Это отчёт пользователя о конкретной конфигурации, а не проверка всех установок Windows 2000.
> Не подтверждены отдельно на Windows 2000: HTTPS-подписки через `nt5helper` с разными наборами
> сертификатов, системы без SP4 или с другим набором обновлений, конфигурация с KernelX для этой
> сборки (ошибку `failed to find ConnectEx` исходного nt5helper 0.9.6 наблюдали на Windows 2000 +
> KernelX; KernelX её не устранял), русский интерфейс, многопроцессорные машины. Процессор с SSE2
> обязателен (`GO386=sse2`).
> На хосте (Windows 11) пути NT 5.0 проверены в режиме имитации (`nt50Simulate`) — это не замена
> проверки на настоящей системе.
>
> Сообщение Diagnostics в программе 0.9.7-dev1 по-прежнему называет «Windows 2000 SP4 with an extended
> kernel (KernelX)» поддерживаемой конфигурацией (`Services/Dependencies.cs`); текст устарел и будет
> исправлен в следующей сборке программы (в протестированный `NekoRayNT5.exe` изменения не вносились).
>
> Ниже — исходный анализ 2026-10-17, **до** переноса рантайма на NT 5.0; его выводы о том, что
> ядро на Windows 2000 не загружается, относятся к сборкам 0.9.6 и раньше.

Статус на 2026-10-17 (исторический, до 0.9.7): Windows 2000 не поддерживалась и не проверялась на
настоящей системе (VM Windows 2000 SP4 в этой работе недоступна). Ниже — что
установлено статическим анализом, что из этого следует и как проверить.

## 2. Доказательства (воспроизводимо)

PE-аудит (только чтение заголовков и таблицы импорта):

```
runtime/xray.exe:      machine=0x14c subsystem=3 subsys-version=5.1 os-version=5.1
  kernel32.dll (40): AddVectoredExceptionHandler CloseHandle CreateEventA ... WriteFile
runtime/nt5helper.exe: machine=0x14c subsystem=3 subsys-version=5.1 os-version=5.1
  kernel32.dll (38): AddVectoredExceptionHandler ...
NekoRayNT5.exe:        machine=0x14c subsystem=2 subsys-version=4.0 os-version=4.0
  mscoree.dll (1): _CorExeMain
```

Из 40 статических импортов `xray.exe` в Windows 2000 отсутствует только
`AddVectoredExceptionHandler`; остальные (IOCP, waitable timers,
SwitchToThread и т. д.) есть с NT 4.0. Self-test `TestExecutableCheck`
проверяет, что программа на «NT 5.0» отклоняет `xray.exe` с понятным
сообщением (подсистема 5.1, Windows XP), а пропавшая функция называется
по имени.

Динамические зависимости Go 1.20 (исходники тулчейна, `go-386.zip`):

| Где | Функция | Минимум |
|---|---|---|
| `runtime/signal_windows.go:31` | `AddVectoredExceptionHandler` — вызывается безусловно при старте каждого процесса | Windows XP |
| `runtime/os_windows.go:130` | `advapi32!SystemFunction036` (RtlGenRandom) — случайные числа рантайма и `crypto/rand` (TLS, REALITY) | Windows XP |
| `internal/poll/fd_windows.go:1008` | `ConnectEx` (через WSAIoctl) — каждое исходящее TCP-соединение | Windows XP |
| `syscall/zsyscall_windows.go:177` | `ws2_32!GetAddrInfoW` — разрешение имён | Windows XP |

## 3. Вывод и блокер

Оболочка (`NekoRayNT5.exe`) по коду совместима с NT 5.0 и на Windows 2000
должна запускаться, показывать профили, импортировать ссылки, `http://`-подписки
и файлы, а в Diagnostics объяснять, что ядро и помощник здесь не работают
(это уже реализовано: `ExecutableCheck` до запуска разбирает PE, сообщение
«Windows 2000: ...» в Diagnostics, Start/URL-тест недоступны с причиной).

**Блокер подключения:** ядро. Любое ядро с VLESS + REALITY написано на Go;
рантайм Go (и XP-бэкпорт) требует как минимум четыре функции Windows XP
(таблица выше). Изменение версии подсистемы в PE этого не решает: процесс
упадёт при первом же вызове.

Варианты (ни один не выполнен; каждый требует отдельного решения):

1. **Портировать рантайм Go на NT 5.0** на базе XP-бэкпорта: обработка
   исключений без VEH (SetUnhandledExceptionFilter / SEH-кадры — глубокая
   переработка, Go опирается на VEH для паник и nil-указателей), запасной путь
   без ConnectEx (блокирующий connect в отдельном потоке), `gethostbyname`
   вместо `GetAddrInfoW`, `CryptGenRandom` вместо RtlGenRandom. Затем
   пересобрать Xray 1.8.3. Объём большой; проверка — только на настоящей
   Windows 2000.
2. **Неофициальное расширенное ядро для Windows 2000** (сторонние проекты,
   добавляющие функции XP в kernel32/ws2_32). Не проверено, системные файлы
   меняются сторонним пакетом — для продукта не рекомендуется, можно описать
   как эксперимент пользователя.
3. **Шлюз:** Windows 2000 использует прокси (HTTP/SOCKS) на другом компьютере
   локальной сети, где работает NekoRay NT5 на XP с включённым «Allow other
   devices to connect». Работает без изменения кода (системный прокси Windows
   2000 можно указать вручную); это не «поддержка Windows 2000» программой.

Один общий проект сохраняется: отдельная сборка для Windows 2000 не нужна,
пока ядро не существует; оболочка уже собирается одна для XP и 2000.

## 4. План проверки на Windows 2000 SP4 (отдельная VM со снимком)

Предусловия: Windows 2000 SP4 + Update Rollup 1, Windows Installer 3.1,
.NET Framework 2.0 (полный распространяемый пакет), IE 6 SP1 (желательно).
Снимок VM до установки. Комплект: `NekoRay-NT5-build-lab\versions\NekoRayNT5-v<версия>`.

| № | Шаг | Ожидается | Записать |
|---|---|---|---|
| W1 | Запустить `NekoRayNT5.exe` | Окно открывается, без падения; журнал: версия NT 5.0, «The core cannot run on this system ... NT 5.1 ... Windows XP» | Текст журнала |
| W2 | Diagnostics | Windows — Note с объяснением; Core и Helper — «cannot run here» с причиной | Copy report |
| W3 | Двойной щелчок по профилю, URL-тест | Понятное сообщение, без падения | Снимок окна |
| W4 | Add: ссылки, Base64, файл, `http://`-подписка | Профили добавляются; `https://` — понятный отказ (нет nt5helper/curl) | Результат |
| W5 | Группы: правый щелчок — создать, переименовать, удалить | Работает | — |
| W6 | Settings → General → Русский, перезапуск | Интерфейс на русском, кириллица без «????» | Снимок |
| W7 | Трей, второй экземпляр, выход | Работает | — |
| W8 | `xray.exe version` в cmd | Ошибка загрузки Windows | Точный текст |
| W9 | Любое падение | `%APPDATA%\NekoRayNT5\logs\crash.log` | Файл |

До успешного W1–W7 Windows 2000 в README указывается как «не проверена»,
подключение — «невозможно (ядро требует Windows XP)».

## 5. Первый опыт W0: исходная точка (план 2026-10-17, не выполнялся)

Цель: на настоящей Windows 2000 SP4 x86 установить две вещи до любого
переноса Xray/Go — (1) работает ли оболочка .NET 2.0, (2) какой именно отказ
даёт загрузчик на `xray.exe` и `nt5helper.exe`. Ничего не собирается и не
меняется; системные файлы Windows 2000 не трогаются.

VM: VMware, гостевая ОС «Windows 2000 Professional», 1 CPU, 256–512 МБ,
диск 4–8 ГБ; свой дистрибутив Windows 2000 Professional SP4. Сеть — только
host-only или отключена (непропатченная Windows 2000 не выходит в интернет;
для W0 сеть не нужна). Установить по порядку: SP4 (если не интегрирован) →
Update Rollup 1 для SP4 → Windows Installer 3.1 → .NET Framework 2.0
(полный x86 распространяемый пакет); VMware Tools — по желанию. **Снимок VM
до копирования программы.** Файлы переносить ISO-образом или общей папкой.

Комплект: копия `NekoRayNT5-v0.9.6-rc2-portfix-test` (проверен на XP),
перед копированием на хосте `sha256sum -c SHA256SUMS.txt`. Профилей и
подписок не нужно; только синтетическая ссылка из `docs/nt5-screenshots.md`.

| № | Шаг (в `cmd`, в папке комплекта) | Ожидается | Записать |
|---|---|---|---|
| W0.1 | `ver`; Панель управления → Установка и удаление: .NET Framework 2.0 | `Microsoft Windows 2000 [Version 5.00.2195]`; .NET 2.0 в списке | Вывод `ver` |
| W0.2 | `set NEKORAY_NT5_DATA_DIR=C:\nt5-w0`, затем `NekoRayNT5.exe` из того же окна | Окно открывается без падения; в журнале окна: `The core cannot run on this system: xray.exe requires Windows NT 5.1 or newer (Windows XP); this system is NT 5.0. Windows refuses to load it.` | Журнал окна (текст) |
| W0.3 | Diagnostics → Copy report (вставить в Блокнот, сохранить) | Windows — предупреждение «Windows 2000: xray.exe and nt5helper.exe need Windows XP...»; Core — «cannot run here» с той же причиной; Helper — «cannot run here» | Файл отчёта |
| W0.4 | Add → вставить синтетическую ссылку `Example VLESS Reality` → Add; двойной щелчок по ней | Профиль добавлен; при подключении — окно «The core cannot run on this system: ...», без падения; `xray.exe` не запускается | Снимок окна |
| W0.5 | Program → Exit; в том же `cmd`: `xray.exe version`, затем `echo %errorlevel%` | Окно/сообщение загрузчика, ожидаемо «xray.exe is not a valid Win32 application.» (ERROR_BAD_EXE_FORMAT, 193); точный текст и код не известны | Точный текст, код |
| W0.6 | То же для `nt5helper.exe version` | Как W0.5 | Точный текст, код |
| W0.7 | Есть ли `C:\nt5-w0\logs\crash.log` | Файла нет | Файл, если есть |

Остановиться и прислать результаты W0.1–W0.7. **Пересмотр после W0, до
любой сборки:**

- W0.2–W0.4 прошли → оболочка — подтверждённая основа; дальше W1–W7 (раздел
  4) и решение пользователя о варианте 1/2/3 (раздел 3).
- W0.2 падает, .NET 2.0 не ставится или окно не открывается → сначала
  разбирается это (оболочка), к ядру не переходить.
- W0.5 показывает не ошибку загрузчика (например, «procedure entry point
  AddVectoredExceptionHandler could not be located» или запуск) → вывод
  раздела 2 пересмотреть до любых правок рантайма.

Только после пересмотра — следующий опыт: минимальная программа Go
(hello world) тем же тулчейном с подсистемой 5.0, чтобы поимённо увидеть,
где останавливается рантайм. Это уже сборка и отдельное решение.
